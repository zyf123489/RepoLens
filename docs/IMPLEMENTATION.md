# RepoLens 实施基线与逐节点核对

依据：`docs/design-v1.0.0.md`（2026-10-23 评审修订稿）及本次会话。用户已授权编码、构建、验证，并追加授权将项目提交、推送至已配置的云端仓库；正式版本发布仍未执行。

## M0：范围与实施决策

- 第一版实现文档 §5.1 必需功能。暂不提供全局编辑、worktree 专属编辑、author/committer 编辑、连接测试、导出、深色主题、自动更新。
- 简体中文、浅色；软件内部版本 `0.1.0-alpha.1`，与设计文档版本分离。未选择开源许可，不能据此宣称开源授权。
- 依赖本机 Git，最终最低要求 2.46；不附带 Git。实际构建工具为 Rust 1.99.1、Node 24.18.0；Node 最低 22.12。
- 初步验证目标：Windows 10 22H2/11 x64；macOS 12+ x64/ARM64；Ubuntu 22.04+ x64。它们都是待验证目标，不构成已通过支持声明。
- SQLite 位于 Tauri app_data_dir，schema 通过 user_version 迁移。默认保留应用数据；不保存仓库状态全文或认证秘密。
- 重复 local 身份键：预览全部原值；保存时替换目标文件中该键的全部直接项，移除时移除全部直接项，不修改 include 文件。
- 身份输入保留精确字符串；拒绝空/纯空白、控制字符、过长值。邮箱为基本语法检查，不验证可收信。
- 确认令牌一次性、短期有效，关联目标、内容、配置来源和上下文指纹；写入前再次校验；冲突要求重新预览。保留 Git 自身锁，不覆盖外部并发变更，不自动补偿。
- SSH 只静态解析 OpenSSH 配置的安全子集。遇到 Match/不支持语法/自定义 SSH 命令即降级，绝不运行 ssh -G、Match exec、ProxyCommand、凭据助手。
- 最终将 Git 最低要求从初步的 2.40 调整为 2.46：旧版本不能仅靠 `GIT_NO_LAZY_FETCH` 保证部分克隆读取不自动补取对象。2.46 的相关检查已核对 [Git 官方源码](https://github.com/git/git/blob/v2.46.0/promisor-remote.c)；同时将所有 Git 子进程的协议允许列表置空，缺失对象按读取失败处理，不启用网络或本地传输补取。该调整落实文档的离线约束，不改变产品业务范围。

## 各节点回溯结论

### M1：架构与呈现

`src/App.tsx` 实现左侧导航、汇总卡片、仓库列表、右侧详情及原生 dialog 确认层。浏览器预览明确提示本地功能需要桌面宿主，不填充模拟业务数据。Git 查询、扫描及写入在 Rust 后台任务执行，IPC 不开放任意命令或任意文件写入。SQLite 只保存条目、分组、规则和 Git 可执行路径，使用 WAL 和 schema 版本检查。

回溯 §14–17：保持正式浅色两级工作台与职责分层。`0.1.0-alpha.1` 为软件内部版本，不冒用设计文档版本作为正式发布版本。CI 文件存在不等于跨平台验收完成。

### M2：发现与只读总览

扫描深度以根目录为 0，默认 3；目录名和相对路径按段精确匹配，不支持通配符；继续发现嵌套仓库，跳过链接、junction、`.git` 和已识别的 bare 内部对象树。扫描结果临时保存，用户勾选后才写入收录表。已收录路径失效时保留条目和错误。

扫描线程的可展开异常会收尾为失败，保留已发现结果；状态锁受异常影响时，轮询与收尾均可恢复为失败状态，worker 统一安全获取状态锁，发现失败状态即返回，不通过 unwrap 再次触发 panic；界面停止加载并允许重新扫描。线程创建失败直接返回错误，不留下运行中的任务；进程被强制终止不在异常收尾保证范围内。

仓库上下文、HEAD、工作区、最近提交、上游、身份和远程分别返回状态、错误与读取时间。暂存/未暂存/未跟踪/冲突允许重叠计数；bare 工作区显示不适用，空仓库显示暂无提交。分组只整理条目；删除分组不删除条目规则，移除收录不删除仓库。

回溯 §6–8、16：普通仓库、worktree、bare、已初始化子模块分别收录；通过实际文件身份判断路径去重。只读测试确认 config、index、HEAD、refs 与工作区文件内容保持不变。刷新最多 3 个条目任务并行，按条目逐步返回，旧批次结果不覆盖新批次。

### M3：身份检查

读取 `user/author/committer` 的姓名、邮箱六键，保留 Git 返回顺序、scope、origin，条件包含交由 Git 求值；不承诺完整包含链。作者/提交者仅在对应键未配置时回退基础身份，显式空值不回退。精确规则区分大小写；完整域名忽略大小写，不隐含子域名；启用约束全部满足、域名候选任一满足；冲突规则拒绝保存。

底层判断明确区分“成功读到值”“成功确认未配置”“未读取成功”：缺少读取结果的键及无法可靠回退的字段显示检查不完整；总状态由统一评估函数产生，其他已知字段继续分别检查。

回溯 §9–10：读取不完整优先于不匹配、缺失、覆盖待核实、未设规则和通过。无规则本身不计入需要检查；工作区修改与认证未知不自动推导身份异常。身份部分读取失败仍显示其余已知键；界面说明实际提交还可能受环境、本次参数和其他工具影响。

### M4：确认写入

前端只提交 `user.name/user.email` 的选定操作，后端再次验证白名单。预览展示目标、全部直接原值、当前生效值、新值/移除操作、继承未知和共享影响。令牌只在内存中存在，一次使用、5 分钟过期；指纹关联 Git、上下文、HEAD、身份和相关来源文件。

指纹还枚举普通/条件 include 声明与 worktree 配置开关，保留顺序并校验声明来源文件内容；不提供身份值的条件引用也参与检查，不自行解释条件，不枚举和记录全部配置。

生成预览前后分别计算指纹，避免将中途变化后的配置误绑定到旧差异。确认后以排他创建方式获取目标 `config.lock`，锁内再次核对指纹；在同目录临时文件中使用 Git 修改全部直接项，不展开写入 include；再次核对后整体替换目标文件，再读取 local 结果和当前生效配置。暂存失败不替换目标；验证失败不报告成功。只清理自己创建的锁，不删除外部锁，不自动回滚他人修改。其他配置来源不共用此锁，因此仍进行来源复核，并在保存后报告实际结果。

回溯 §12–13：编辑不等于修改作者/提交者/worktree 覆盖；移除直接项不等于生效为空。已有 worktree 关联按 common Git dir 展示，未收录的关联可能未列出。确认前不触碰目标配置，取消不写入；外部修改使旧预览失效并保留用户输入。

### M5：认证元数据

按每个 remote 的 fetch/push 地址分别展示。地址的用户名、密码、查询串和 fragment 在 Rust 返回前移除；可能包含内联命令与凭据的自定义协议地址隐藏内容，仍展示协议类型；本地 Windows 路径单独处理。自定义助手内容隐藏，空 helper 保留“重置此前助手列表”，其他适用项按 include/scope 原顺序保留。URL 作用域以独立公开标记调用 Git URL 匹配器逐项检查，不调用凭据 API。实现参考 [Git credential 配置处理](https://github.com/git/git/blob/v2.55.0/credential.c) 与 [Git 配置文档](https://git-scm.com/docs/git-config)。

SSH 仅解析用户 `.ssh/config` 的 Host/否定匹配和首值，展示 HostName/Port/User/IdentityFile/IdentitiesOnly。Include 未展开、Match 后续停止、特殊展开/引号语法不推断；自定义 SSH 命令/变体显示限制。代理命令仅提示存在。系统 SSH 配置、agent 和最终密钥选择未验证，不打开私钥、不运行 ssh -G。

回溯 §11、13：所有端点都是“未测试”，配置不能证明账号、凭据存在或认证成功。HTTPS 候选用户名原值保守隐藏，以防 Token 被配置为用户名；当前只展示“已配置”及来源。这是对 §11.3 展示深度的已记录限制，不声称完整账号识别。不能可靠匹配的部分凭据作用域显示限制。

### M6：交付与实际验证范围

本次完成 Windows 可运行内部版及可复现验证脚本；具体证据、性能数字、文件校验值和未验收项目见 [验证记录](VERIFICATION.md)。正式发布门槛仍按 §21.1 执行，不能用内部包替代独立环境安装、最低依赖、卸载和跨平台交互验收。

## 数据、备份与卸载

应用数据目录通过 Tauri 的系统目录解析，可在设置查看；schema 当前为 1，启动时建表并拒绝高于当前支持版本的数据库。手工备份/恢复须先退出全部实例，复制整个应用数据目录，避免仅复制 WAL 模式下的主数据库。当前没有自动备份或跨版本降级工具。

NSIS 生成脚本的卸载页提供“删除应用程序数据”复选框，默认未勾选；只有用户勾选才删除应用数据目录。移出列表或卸载不主动删除外部仓库。此项已核对生成脚本，实际卸载交互仍待独立环境验证。

## 必须保持的业务不变量

1. 扫描结果用户勾选后收录；停止保留已发现结果；链接不递归。
2. worktree 条目与规则独立，local 写入按共享资源协调。
3. 身份分别检查 user/author/committer；状态优先级与 §10.4 一致。
4. 未设置规则不自动认定错误；缺失仍提醒；局部失败不变成零值。
5. 仓库写入只允许 local user.name/user.email，经具体预览确认后执行。
6. 刷新、扫描、认证概览不联网、不执行配置脚本、不获取秘密。
7. 前端/SQLite/日志只接收经过脱敏的认证元数据。
8. 构建成功、交互验证、安装验证、正式发布分别记录。
