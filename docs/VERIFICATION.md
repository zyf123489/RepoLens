## 性能基线

测试机：Windows 10 Pro 22H2，build 19045.6466；Intel Core i5-14400；系统报告物理内存 34,008,203,264 字节（约 31.67 GiB）；磁盘 YMTC YMSS2EB08B66MC；Git 2.55.0.windows.1。Rust 1.99.1，Node 24.18.0。硬件信息在测量后补采，测试期间另有开发/构建任务，结果仅为初步基线。

方法：`cargo run --manifest-path src-tauri/Cargo.toml --example benchmark`。本次是 **debug 核心构建**、刚生成的临时数据、OS 缓存未清空的首次读取；3 个并行任务，依次读取仓库上下文、HEAD、工作区、提交、上游、身份及远程。不是 Release UI 冷启动、也不是应用缓存命中测量。

| 条目数 | 独立仓库 | linked worktree | 全量读取耗时 | 失败 |
| ------ | -------- | --------------- | ------------ | ---- |
| 10     | 9        | 1               | 3,311 ms     | 0    |
| 100    | 90       | 10              | 28,402 ms    | 0    |
| 500    | 450      | 50              | 141,348 ms   | 0    |

所有档位包含同一个 10,000 文件的未跟踪工作区，文件量 10,000、未跟踪量 10,000；目录层级按样例根为 0 最深为 6。其他样例为空仓库或空提交，不能代表大型历史仓库。扫描根目录深度 1 发现全部 500 条目，耗时 143,412 ms。原始结果：`artifacts/benchmark.json`；数据生成方式位于 `src-tauri/examples/benchmark.rs`。

500 条目的完整刷新偏慢；界面会逐条返回结果，不等待整批完成才展示。后续应优先合并 Git 查询与复用同一读取上下文，再以 Release 构建重测。冷/热启动、峰值内存、空闲 CPU、Git 子进程峰值及统一性能阈值尚未完成验收。任务并发上限 3 为实现配置，不当作进程采样结果；不宣称已通过“轻量”定量指标。
